Help: sending data packets

Drones send JSON to POST /api/packet. No login or key is needed to send or read packets.

Send one packet

Reply 201: {"status":"ok","packetId":"…","seq":42}. The packet appears on the Data packets page within a second.

Send several at once (up to 100)

Send a JSON array. All packets are checked first: if any is invalid, none is stored and the reply is 400 with every problem listed, e.g. packet 2: lon is required.

Packet fields

FieldMeaningRequiredRule
idDrone / tag IDyes1-64 letters, digits, . _ -; a whole number (1005) is stored as text
latLatitudeyesnumber −90 … 90, up to 8 decimals (e.g. 23.07814312)
lonLongitudeyesnumber −180 … 180, up to 8 decimals; lat = 0 and lon = 0 together is refused (no GPS fix)
AltAltitude, metresnonumber −1000 … 100000
Alt_RAltitude referencenotext up to 40 characters (e.g. MSL, AGL) or a number
d_x, d_y, d_zDeltasnonumbers −1000000 … 1000000
TimestampDevice timenoYYYY-MM-DD HH:MM:SS in IST (no zone), ISO 8601 with a zone, or Unix seconds
  • Field names are matched ignoring case, spaces, _ and -: Alt_R = alt_r = AltR, d_x = dx.
  • Older long names also work: TrackerId, Latitude, long / Longitude, Altitude, Altitude Reference, delta_x / deltaX (and y / z).
  • Numbers may be sent as text ("16.5"). Missing optional values are stored as empty. Unknown fields are not stored; the reply lists them in ignoredFields.
  • The Content-Type header is optional. Body limit: 1 MB.
  • The device time is used when it is at most 10 minutes ahead of, or 7 days behind, the arrival time. Otherwise the arrival time is shown, marked (received).

Map

The Map page draws the path of one drone from its data packets: a green pin where the path starts and an arrow at the current position, pointing where the drone is heading. New packets move the arrow without refreshing the page. Choose the drone at the top; untick Follow the drone to look around freely, and click any point for its time, position and altitude. Switch between street map and satellite with the button in the top-right corner of the map.

Sensors and configuration files

On the Settings page you add sensors (for example a Node sensor and a separate sensor; any number) and upload each sensor's configuration file with a version number (numbers separated by dots, e.g. 1.2; each new version must be newer than that sensor's current one). Every sensor has its own files, versions and APIs, no login needed:

  • GET /api/sensors: all sensors and their latest version.
  • GET /api/sensors/node-sensor/config/version?current=1.1: answers only status, updateAvailable, version, fileName and contentType. updateAvailable is true when the uploaded version is newer than the drone's own version.
  • GET /api/sensors/node-sensor/config/download: that sensor's latest file (exact bytes). ?version=1.1 gets an older one. Headers X-Config-Version and X-Config-SHA256 let the drone check the download.

Thrust-bench firmware

The Firmware page holds the OTA releases for the bench boards main (ESP32), n1 and n2 (ESP32-C3). Firmware contains the bench passwords, so you need the engineer role to download it and the admin role to upload. New accounts have no firmware access: an admin gives it on the Users and API tokens page.

  • Engineers: download a release before going to the bench (its WiFi has no internet). Take the .tbfw package (manifest + image in one file) or "Download all three" for the compatible set, and open it in the bench dashboard's config tab. Yanked releases are greyed out and ask before downloading.
  • Admins: Upload and manage → choose the .ino.bin (not the .merged., .bootloader. or .partitions. file), target, version (e.g. 2.1.0), proto, requires and notes → the upload becomes a draft → check the values the server computed → Publish (type the target to confirm). A published release never changes: to fix a mistake, yank it with a reason and upload a new version.
  • Bench dashboard / scripts: create an API token on the Users and API tokens page and send Authorization: Bearer <token> to /api/tb/v1/…, e.g. GET /api/tb/v1/firmware/latest?target=n1 or GET /api/tb/v1/firmware/compatible-set. Downloads support Range, so a broken download can resume. All endpoints are in the API docs (Firmware).

Read packets

  • GET /api/packet?limit=200: newest packets of all drones (oldest first, max 5000).
  • GET /api/packet/1005: one drone (ID not case-sensitive).
  • ?since=<seq>: only packets newer than that sequence number.
  • GET /api/packet-stream: live feed (Server-Sent Events).
  • GET /health: service and database status.

Full reference with examples: API docs.

Errors

Every error is JSON: {"status":"error","message":"…","errors":["…"]}.

  • 400: invalid JSON or invalid packet (nothing stored).
  • 404: unknown endpoint or a drone with no packets.
  • 413: body larger than 1 MB.
  • 503: the database is unreachable; send again later.
